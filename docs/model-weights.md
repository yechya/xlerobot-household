# 模型权重范围与复用边界 (Model Weights Scope)

本仓库是**框架与端到端管线**，不是“下载即用”的成品模型分发。仓库默认不包含训练权重；本地出现的
checkpoint 是实验室验证产物，不应被视为跨部署可用的通用模型。

## 仓库提供什么

| 提供 | 不提供 |
|------|--------|
| 三路 RGB 观察、证据校验与任务契约 | 通用家务操作权重 |
| 遥操作采集、数据集整理、训练入口 | 覆盖多样家庭环境的数据集 |
| SmolVLA / π0.5 的 ONNX 导出、TensorRT 编译与可插拔推理后端 | 对任意相机/机械臂安装的即插即用适配 |
| `robotd` 安全授权、mission 编排、失败恢复与 episode 记录 | 跨硬件保证的动作精度 |
| 版本化 policy registry、SHA-256 绑定与 benchmark 门禁 | 未经重新评测的成功率承诺 |

## 本地权重的真实含义

现有权重（例如 `fold_simple`、`pick_up_bottle`、`operate_drawer`）是在固定实验室条件下采集的
几十条遥操作 episode 上微调得到的：

- 相机型号、安装位置、视场角与曝光固定；
- 桌面高度、光照、背景与物体摆放分布固定；
- 机械臂标定、舵机零位与夹爪结构固定；
- 训练数据的动作归一化统计量绑定当前机器人。

因此策略学到的是**这套配置的先验**，而不是可迁移的通用操作技能。即使外部用户使用相同型号硬件，
相机安装偏差几厘米、桌面高度变化或光照不同，都可能造成显著掉点。视频中的成功片段也不代表
统计成功率；真实成功率必须以 benchmark 报告为准。

## 直接复用为什么会失败

1. **观测分布偏移**：相机内参/外参、分辨率、色彩与帧率不同。
2. **动作空间偏移**：关节零位、方向、单位与夹爪行程不同。
3. **归一化统计不一致**：pre/postprocessor 的均值、方差随数据集变化。
4. **任务语义不一致**：训练时的语言指令字符串与部署时不同。
5. **场景先验失效**：背景、物体外观、桌面材质与布局变化。
6. **时序与延迟不同**：推理后端、控制频率与动作平滑参数变化。

## 有意义的复用方式

外部用户应把本地权重当作**参考实现**，而不是成品：

1. 使用本仓库的遥操作与录制流程采集自己的数据；
2. 按自己的相机与机械臂重新标定，更新硬件 profile；
3. 重新训练 SmolVLA / π0.5，或至少重新拟合归一化统计；
4. 运行 ONNX 导出与 TensorRT 编译脚本，记录后端与精度；
5. 用 benchmark 门禁评估成功率、接管率与失败阶段；
6. 通过 policy registry 显式绑定新权重的 SHA-256 与部署指纹。

只有完成上述闭环，模型才进入任务 catalog 的真实执行路径。

## 确定性能力不依赖权重

`dock_table` 的桌沿对接、mission 重试/恢复、安全急停、Token 授权与证据校验属于框架层能力，
不依赖某个微调权重。它们同样需要按现场标定（table profile、相机映射、串口绑定），但不需要
重新训练策略。

## 安全声明

任何真实硬件动作都必须在物理急停可用、工作区清空、人员远离的条件下进行。仓库不附带任何
安全认证；使用者对部署现场的硬件改动、标定误差与操作风险负全部责任。
